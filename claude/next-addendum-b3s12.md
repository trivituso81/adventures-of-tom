|---|---|
| Pattern | Stage 12 (CHANGES `b3s12a`, `b3s12b`, `b3s12`) is the pattern: one data file per chapter (`data/b3-foes-chNN.js`), a chapter section added to `tools/b3-check-s12.js`-style check file (stage 13 gets `tools/b3-check-s13.js`, registered in `tools/b3-sim.js`), Lab fights appended to `data/b3-lab.js` (NEW 45 on), a script tag in `index.html` after the previous chapter file, a `stage13` function in `tools/b3_test.py` (copy `stage12`). |

| Foe ids | A foe id must equal the id of the old monster in `data/*-monsters.js` (`MONSTERS[id]`), or the Lab fight crashes in `b3LayoutFoes` (`b2BattleDef(undefined)`). The simulator does not load `MONSTERS`, so only the browser test catches it. Check every new foe id with `grep -n "^  <id>:" data/*monsters*.js` before the browser run (stage 12 hit it: `popup`, not `popuppanic`). |
| Git | The clone is shallow. If `git rebase` shows add/add conflicts everywhere there is no merge base: abort, `git fetch --unshallow origin main`, `git merge --ff-only origin/main` (stash first), then pop the stash. On a conflict in `data/board.json` take upstream and re-apply the card edit; in `docs/CHANGES.md` keep both entries, yours first. |
| Seams added in stage 12 | Act field `starts` (first use starts the repeat's count); act conditions `noAllyId`, `allyAge`; targets `randomFrontAlly`, `unshielded`; ops `eat`, `hpLoss`; foe field `onKo` (effects run when that monster is knocked out and not eaten); summon with printed `hp` and `ifNoFront`; flag `foeTaunt` (family must target the putter).
